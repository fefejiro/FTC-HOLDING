## 4. P0 Blockers

### Blocker 1 — Railway API service is paused
- README ([APPS/saywetin/README.md](APPS/saywetin/README.md) line 35) explicitly states: *"keep `sunny-acceptance` intentionally paused unless SayWetin needs active server-side processing again."*
- Until unpaused (or until `/v1/slang/explain` and `/api/identify-by-text` are migrated to the peacepad-extension worker that the web client already falls back to), the new endpoints cannot serve traffic.
- The currently shipped v1.2.2 (versionCode 23) is presumably already broken for recognition in prod for the same reason.

**Resolution paths:**
1. Unpause `sunny-acceptance` on Railway (cost re-incurred). Fastest. Restores all SayWetin functionality.
2. Move the two new endpoints into `workers/peacepadai/` Cloudflare worker so they are zero-cost and always-on.
3. Stand up a tiny Cloudflare Worker dedicated to SayWetin AI endpoints (gpt-4o-mini calls only), keep ACRCloud calls deferred to Railway later.

### Blocker 2 — `EXPO_PUBLIC_API_BASE_URL` not baked into AAB
- No `.env` file at `APPS/saywetin-native/`.
- `eas.json` does not declare an env map for production.
- All three native API clients ([listen.ts](APPS/saywetin-native/src/api/listen.ts), [live-lyrics.ts](APPS/saywetin-native/src/api/live-lyrics.ts), [slang.ts](APPS/saywetin-native/src/api/slang.ts)) read `process.env.EXPO_PUBLIC_API_BASE_URL` and throw at runtime if absent.
- The just-built v1.3.0 AAB has none baked in. Even if Railway is unpaused, the app cannot reach it.

**Resolution:** Create [APPS/saywetin-native/.env](APPS/saywetin-native/.env) with `EXPO_PUBLIC_API_BASE_URL=<chosen-host>` and rebuild bundleRelease. Confirm with another bundle scan before submission.

6. **Submit to Play Console internal track** only after on-device smoke passes.
