# Interview Prep Template

Use this when a recruiter conversation turns into an interview, prep call, or shortlist notice. The goal is to convert the email thread, submitted resume, job details, and prep materials into a focused interview pack that is truthful, rehearsable, and weighted to the client's scoring grid.

## 1. Source Intake

Capture these fields before writing answers:

| Field | Value |
|---|---|
| Candidate |  |
| Recruiter / agency |  |
| Client |  |
| Role / requisition |  |
| Work location |  |
| Duration / contract type |  |
| Interview date/time |  |
| Prep call date/time |  |
| Submitted resume file |  |
| Prep document / JD file |  |
| Recruiter notes |  |

Trust level:

- `high`: recruiter confirms shortlisted/interview, attaches submitted resume or prep document, and gives client-specific details.
- `medium`: recruiter asks for availability or confirms submission, but interview is not scheduled yet.
- `low`: job alert, no-reply board email, or generic "matched with a job" message. Do not build interview prep from this alone.

## 2. Conversation Pattern To Preserve

A real interview-leading conversation usually has these signals:

- Named recruiter from a real agency or employer.
- Direct congratulations, shortlist, interview, or prep-call language.
- Client named clearly.
- Resume submitted to client or attached for review.
- Interview prep document, JD, calendar invite, or meeting link attached.
- Must-haves, responsibilities, scoring criteria, or stakeholder expectations included.

If the message is from a job board/no-reply sender, mark it `apply_only_no_reply` and do not create recruiter replies or interview prep.

## 3. Scoring Grid

Break down the role by weight. Spend prep effort in the same proportions.

| Criterion | Weight | What they are testing | Candidate evidence |
|---|---:|---|---|
| Requirements / core BA |  |  |  |
| Agile / delivery |  |  |  |
| Domain fit |  |  |  |
| Tools / platform |  |  |  |
| Behavioral / communication |  |  |  |

Rule: answer the highest-weight criteria first and deepest. Do not over-index on tools if tools are only a small part of the score.

Use honest bridge language for gaps:

> I have not worked in [exact domain] by name, but the workflow structure is familiar: [case lifecycle / approvals / audit trail / data validation]. My value is the analysis discipline: modelling the lifecycle, defining rules and exceptions, and turning that into testable requirements.

## 5. Story Bank

Prepare 8 to 12 reusable STAR stories. Each answer should include:

- `Question`
- `What they are testing`
- `Situation`
- `Task`
- `Action`
- `Result`
- `Reusable proof words`
- `Numbers to remember`

Recommended story categories:

1. Vague problem to development-ready requirements.
2. Acceptance criteria and Definition of Ready.
3. Data analysis / SQL / current-state investigation.
4. Requirements artifacts for business and technical audiences.
5. Domain scenario using transferable workflow logic.
6. Stakeholder conflict or prioritization under pressure.
7. Mid-sprint requirement misunderstanding or UAT defect.
8. Accessibility / compliance / audit-conscious requirement.
9. End-to-end BA leadership on a complex initiative.
10. Hard deadline under pressure.
11. Explaining a complex technical issue to non-technical leaders.
12. Role-boundary / maturity question.

## 6. Answer Style

Use this answer shape:

1. Direct one-sentence answer.
2. Concrete project context.
3. Named BA method or artifact.
4. Stakeholder / delivery action.
5. Measurable or observable result.
6. Tie-back to the role.

Avoid:

- Inventing domain experience.
- Memorizing long scripts verbatim.
- Talking only about tools.
- Giving generic "team player" answers without artifacts or outcomes.
- Claiming ownership that belongs to the Product Owner, architect, developer, or QA lead.

## 7. Final Prep Checklist

- 60-second positioning summary.
- Two domain-bridge stories.
- One data/current-state analysis story.
- One stakeholder conflict story.
- One UAT/acceptance-criteria story.
- Three to five role-specific numbers memorized.
- One clean explanation for any resume timeline concern.
- Two smart questions for the panel.

## 8. Follow-Up Template

```text
Hi [Recruiter Name],

Thank you for setting up the prep call and sharing the interview materials for [Role / Req].

I reviewed the submitted resume, job requirements, and prep document. I am ready to discuss the role with emphasis on [top weighted criterion], [second criterion], and [domain/tool requirement].

For the interview, I will anchor my examples around [project 1], [project 2], and [project 3], and I will keep the answers focused on requirements clarity, stakeholder alignment, Agile delivery, and measurable outcomes.

Regards,
[Candidate Name]
```
