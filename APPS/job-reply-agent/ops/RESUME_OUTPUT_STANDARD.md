# Resume Output Standard

## Purpose

This standard defines how the Job Reply Agent must generate resumes going forward.

The goal is to produce a real professional resume, not a document that explains how it matches a job description. The resume should look and read like a strong human-written resume that happens to be customized to the opportunity behind the scenes.

## Standard Template

Use the orange resume format as the default visual and structural standard for generated resumes.

The approved standard is the cleaner orange-style resume format with:

- professional header
- clear title line
- professional summary
- core skills
- tools and platforms where appropriate
- professional experience
- education and certifications
- clean spacing
- no visible automation language
- no visible job-agent language

The older generated format should not be used as the default because it can read like a job-description response instead of a resume.

## Forbidden Resume Language

Generated resumes must not include these phrases or concepts in the visible resume content:

- tailored resume
- tailored
- target role alignment
- strong fit for
- fit for this role
- aligned with this job description
- based on the job description
- RQ number in the title or footer
- this resume is customized
- generated by
- job agent
- application package

The file name may include internal identifiers when useful for tracking, but the visible resume content must not expose those terms.

## Resume Should Not Describe the Job Posting

The resume should not restate the job description as if it is answering a screening question.

Avoid language like:

```text
Strong fit for Land and Resources Cluster initiatives requiring business process mapping, approvals, incidents, compliance workflows, information management principles, and technology solution specifications.
```

Use professional resume language instead:

```text
Experienced in business process mapping, workflow analysis, information management, compliance-aware documentation, stakeholder engagement, and technology solution specification across public sector and enterprise systems environments.
```

## Summary Section Standard

The professional summary should be natural and role-specific without naming the requisition or saying it is tailored.

Good summary pattern:

```text
Senior Business Analyst and I&IT delivery professional with 15+ years of experience leading requirements discovery, stakeholder engagement, process modelling, data analysis, UAT, Agile delivery support, and enterprise systems modernization across public sector, retail, supply chain, logistics, and technology environments.
```

Avoid summary pattern:

```text
Strong alignment with RQ11067 Business Analyst and Land and Resources Cluster requirements.
```

## Skills Section Standard

Skills should be role-relevant but not excessive.

Use natural skill groupings:

- Business Analysis
- Requirements Gathering
- Stakeholder Engagement
- Current-State and Future-State Analysis
- Business Process Mapping
- Use Case Modelling
- User Stories
- Acceptance Criteria
- Backlog Refinement
- Sprint Ceremonies
- Product Owner Support
- UAT Planning
- Data Analysis
- Oracle / SQL
- Azure DevOps
- Jira / Confluence
- SharePoint
- Information Management
- AODA Awareness
- Public Sector Delivery
- Executive Reporting

The skills section should not look like a pasted keyword dump.

## Experience Section Standard

Experience bullets should use this structure:

```text
Action + scope/context + method/tool + business outcome
```

Good bullet:

```text
Translated policy, operational, data, and compliance requirements into testable scenarios, traceability matrices, validation plans, and implementation support documentation for Ontario public sector modernization initiatives.
```

Weak bullet:

```text
Worked on requirements and supported stakeholders.
```

## Truth and Credibility Rules

Do not invent:

- employer names
- dates
- job titles
- tools
- certifications
- education
- submitted applications
- government program ownership
- direct experience with a domain that is only adjacent

Use bridging language when needed:

- public sector adjacent
- government modernization support
- Oracle environments
- AODA-aware documentation
- compliance-aware validation
- OPS-style business analysis
- Agile and hybrid delivery

## File Naming Standard

The saved file name may include role and company/requisition for internal tracking.

Acceptable internal file name examples:

```text
Fejiro_Efiuvwere_Business_Analyst_RQ11067.docx
Fejiro_Efiuvwere_Business_Analyst_Ministry_Public_Business_Service_Delivery.docx
```

Avoid visible document footer text such as:

```text
Tailored Resume
```

## Validation Gates

Before a generated resume is marked ready:

1. The orange resume format is used.
2. The visible resume text does not contain forbidden language.
3. The resume does not include a section called `Target Role Alignment`.
4. The resume does not say `tailored` anywhere in visible content.
5. The summary reads like a professional resume summary.
6. Skills are relevant but not stuffed.
7. Experience bullets are role-relevant and evidence-based.
8. Dates and titles remain truthful.
9. The DOCX opens successfully.
10. The layout renders cleanly without broken tables or overlapping text.

## Required Code Changes

The current `resume_tailor.ts` behavior is too shallow because it mainly swaps the first title text run and writes an output file. The generator should evolve into a real resume composer that:

- clones the approved orange template
- replaces structured content blocks
- removes all visible tracking or tailoring labels
- writes a natural professional summary
- writes role-relevant skills
- writes selected and reordered experience bullets
- validates forbidden language
- validates the DOCX output
- logs resume evidence separately from visible resume content

The evidence log can say a resume was generated for a role. The resume itself should not say that.

## Definition of Done

The Job Reply Agent resume standard is complete when:

- every generated resume uses the approved orange format
- no generated resume says `tailored` in visible content
- no generated resume contains `Target Role Alignment`
- no generated resume describes the job posting directly
- generated resumes read like professional resumes
- resume evidence is captured in logs, not leaked into the resume
- tests cover forbidden phrases and template usage
