# Next game release plan: one canonical source, two verified artifacts

Saved from the Just Checking In closeout on 2026-08-26.

## Goal

Maintain one canonical Unity codebase and build both store candidates from the
same source commit. Keep the Android AAB and iOS IPA separate because each
platform requires different packaging, signing, entitlements, version fields,
and store metadata.

## Required structure

- One Git-tracked Unity project is the only build input.
- Platform-specific behavior is isolated behind Unity build settings or
  platform defines; gameplay and UI remain shared.
- Android and iOS builds are generated by CI or the checked-in build scripts
  from the same commit SHA.
- Every release writes a provenance record containing source SHA, Unity version,
  target, marketing version, platform build/version code, signing identity, and
  artifact SHA-256.
- Store metadata, screenshots, privacy declarations, and review notes are kept
  beside the release evidence and never inferred from an older artifact.

## Release sequence

1. Freeze and tag the source commit.
2. Run EditMode and PlayMode tests.
3. Build the Android AAB and iOS IPA from that exact commit.
4. Verify bundle/package IDs, versions, target SDK, signing, permissions, and
   hashes.
5. Run fresh-install, upgrade, relaunch, offline, background/resume, and core
   flow smoke tests on both platforms.
6. Upload each artifact to its store and record the portal status.
7. Submit only after declarations and metadata match the tested artifact.
8. Treat uploaded, in review, approved, and public as separate states.

## JCI lessons carried forward

- Never build Android from `just-checking-in-game-clean` or another untracked
  copy when the canonical source is elsewhere.
- Do not treat a successful upload or review submission as public release.
- Resolve or explicitly record Play policy warnings; do not silently bypass
  them.
- Require action-time owner confirmation for policy attestations and final
  submissions.
- Keep optional services such as Play Games disabled unless the product and
  privacy scope explicitly require them.

## Target automation

- Add a JCI-style Android workflow alongside the existing iOS workflow.
- Fail the build if the requested source path is not the canonical checkout.
- Generate one release-manifest JSON file linking the AAB and IPA to the same
  source SHA.
- Add a lightweight Codex release skill only after the provenance checks are
  enforced in CI.

## Estimated effort

- Canonicalization and provenance: 0.5–1 day.
- Android workflow and parity build: 1–2.5 days.
- Policy remediation and cross-platform QA: 0.5–2 days.
- Documentation/skill packaging: 0.5 day.

Expected total: 2–4 working days when no SDK stripping is required; 4–7 days
if identifier-related SDK paths require removal and another full QA cycle.
