# Idea Triage Matrix

Last updated: 2026-03-19
Owner: FTC HOLDING / Una Labs

## Purpose

This system exists to stop every new idea from becoming a live priority.

The default problem is not lack of ideas.
The default problem is too many valid ideas competing for attention at once.

This matrix forces classification before action.

## Core Rule

A new idea is not active work until it survives triage.

If it is not clearly:
- making money now
- strengthening the flagship product
- increasing internal leverage
- or deliberately parked

then it should not take time from current execution.

---

## The Four Buckets

### 1. Sell Now
Use when the idea can reasonably help create revenue, meetings, or sales assets in the next 30 days.

Examples:
- productized service offer
- niche landing page tied to outreach
- fast automation setup
- demo asset for current buyers
- proposal template improvement

Questions:
- Can this help close a deal soon?
- Can it support outreach immediately?
- Does it make the offer easier to explain or buy?

Default home:
- Una Labs
- sales assets
- offer pages
- proposal / outreach systems

### 2. Build Later
Use when the idea is valid, but not worth active attention right now.

Examples:
- future product concept
- larger feature set without urgent pull
- roadmap item with no current forcing function
- a better version of something already good enough

Questions:
- Is this a good idea, just not now?
- Would doing it now displace more valuable work?
- Does it depend on future clarity, validation, or cash?

Default action:
- park it with one line of context
- do not let it live in the daily dashboard

### 3. Internal Leverage
Use when the idea reduces repeated manual work, improves execution, or lowers future cognitive load.

Examples:
- dashboard systems
- documentation improvements
- reusable templates
- workflow automation for your own operations
- internal tracking systems

Questions:
- Will this reduce repeated decisions?
- Will this save time more than once?
- Will future-you or future operators benefit clearly?

Default home:
- operator docs
- internal systems
- ATEAM / execution infrastructure when appropriate

### 4. Ignore / Park
Use when the idea is interesting but not currently useful enough to justify attention.

Examples:
- random interesting experiment
- extra brand concept
- feature with no audience pressure
- low-leverage optimization
- work that is emotionally tempting but operationally weak

Questions:
- Is this just interesting?
- Is this a distraction disguised as opportunity?
- Would I still do this if cash and focus were already solved?

Default action:
- park it
- do not debate it endlessly
- revisit only if reality changes

---

## Triage Questions

Run every new idea through these in order:

### 1. Does it help cash soon?
If yes, it probably belongs in **Sell Now**.

### 2. Does it clearly support the flagship product?
If yes, it may be **Build Later** or active product work, depending on current focus.

### 3. Does it reduce repeated work or mental load?
If yes, it probably belongs in **Internal Leverage**.

### 4. Is it mostly interesting but not important?
If yes, it belongs in **Ignore / Park**.

---

## Promotion Rules

Ideas may move between buckets, but only with a reason.

### Promote from Build Later to Sell Now if:
- real buyer interest appears
- it clearly supports a live offer
- it improves near-term revenue odds

### Promote from Ignore / Park to Internal Leverage if:
- the same pain shows up repeatedly
- it now removes a known bottleneck
- it helps restart speed or clarity

### Demote from Sell Now if:
- it is not actually helping close work
- it is harder to explain than expected
- it causes more build effort than value

---

## Daily Operating Rule

Only **Sell Now** and current approved **Internal Leverage** items should compete for daily attention by default.

**Build Later** should be visible but inactive.
**Ignore / Park** should be recorded once and then left alone.

## If Unsure

If an idea feels emotionally exciting but operationally unclear:
- do not activate it
- put it in **Build Later** or **Ignore / Park**
- return to current priorities

Clarity beats novelty.
